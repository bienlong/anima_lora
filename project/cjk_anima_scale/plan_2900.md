## 5. Code before the first launch — done 2026-09-27

Built as below; line tests 80 / 80 (`tests/test_line.py`: `test_budget_rule`,
`test_plan_groups_take_the_budget`, `test_ruler_sample`, `test_single_ruler`,
`test_merge_rows`, the front-door `merge` parse). What differs from the
draft:
- 1 → `cjk_scale/budget.py`: rows with provenance, like `windows.py`, today
  one row (cold single 150). A factor scales both `train.STEPS_PER_VOCAB` and
  `builder.ITEMS_PER_VOCAB`. **A run's vocabs must share one factor**: the
  builder and batcher draw uniformly, so a mixed run would spread its budget
  evenly. `run_factor` refuses it; split the run and merge. Steps are
  per-row × the run's idx, as before. Warm singles are unchanged
  (factor 1), so the A0 jobs ran on identical code paths.
- 2 → `eval.RULER_N = 24`, and `ruler_sample` draws round-robin over
  glyph-count strata (so 8 per count at 3 / 4 / 5). The piece ruler keeps
  the `read` strings' pieces first. Its old sample (the `word` group's 8) is
  gone, so an old run re-evaluated renders new floor keys. **A's read is 24
  of the 305** (one stratum), not "the 58 in full plus 24 of the 247" of § 1.
  A0's 12 floor keys sit in `native_densea0/`, not `native_single/`.
- 3 → `cjk_scale/merge.py`: the first run is the base. Each other run's idx
  (its `vocabs.json` through the tokenizer, `train.vocab_idx`) overwrite the
  base rows, and a vocab cold in its run is appended (ids sorted). Refused:
  overlap, different seeds, a `line` mode, a stopped-early file. CPU, no
  `--submit`. **Not built:** evaluating the merged dir (`eval` wants a run
  toml + a data dir with `eval.json` / `vocabs.json`).
- 4 → the files, cut by a one-off script (not kept). The headers record each
  cut. Dense: ink ≥ 10.98 reproduces § 1's 58 + 247, because 旅 and 落 read
  703 px with `src/eval/cf_sense.py::_glyph_ink`, 704 in the draft's measure.
  C: § 3's counts. Run tomls: A / C-k read the single ruler only; B / C-p
  read `run0925_300f`'s sent strings (cached floor).

The draft:

1. **Budget rule** (`train.py` + `builder.py`): steps and items per vocab by
   kind × glyph count × warm/cold. Cold single: 150. 3+-glyph piece: B0's
   number. Everything else: 90. Items scale with the steps. A run's steps are
   the sum over its vocabs. Provenance: `stage_i` § 5, and B0's report. This
   is a rule, not a run key (plan.md § 2).
2. **`single` native ruler** (`eval.py`, mirroring `piece`): the run's single
   vocabs rendered alone, `en`, with floor keys through
   `ensure_native_floor`, and per-glyph official / contained in `reads.json`.
   Its sample size and the piece ruler's cap (8 today) become one rule: all
   of a run's vocabs up to 24, then a seeded sample stratified by glyph count.
3. **`merge` verb** (`scale.py <out> merge <run>…`): disjoint rows from the
   same seed, with the `row_scale` rescale. It refuses overlapping idx.
4. Vocab files: `ja_dense_k_0927_305.txt`, `ja_long_p_0927_521.txt`,
   `ja_cold_1901_2900_{k,p}.txt`. They use `ja_cold_0001_1900.txt`'s TSV
   columns, and each header records its cut. Plus
   `configs/runs/run0927_{dense_k,long_p,cold_k,cold_p}.toml`. After B0
   the two piece files split by glyph count (`ja_long_p{3,45}_…`,
   `ja_cold_1901_2900_p{23,45}_…`) and so did the runs
   (`run0927_{long_p3,long_p45,cold_p23,cold_p45}`); the combined files
   stay as the cut record.
